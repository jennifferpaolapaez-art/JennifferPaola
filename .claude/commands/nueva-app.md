NUEVA APP — desde cero, cualquier nicho, con dirección de arte derivada (referencia opcional)
(Requiere: el sistema en docs/sistema/. La imagen de referencia es OPCIONAL.)

Voy a crear una app desde cero. Sigue el protocolo de docs/sistema/INICIO.md
con las respuestas adelantadas del contexto de abajo.

━━━ CONTEXTO (tu nicho + tu idea: qué hace, para quién, qué la hace única · di si adjuntas referencia) ━━━
$ARGUMENTS

Si el contexto viene vacío, pregúntame primero el NICHO y la idea — o ejecuta el FLUJO A de
docs/sistema/INICIO.md para proponerme oportunidades investigadas y dejarme elegir.

⚠️ EL NICHO NO CAMBIA EL PROTOCOLO — LO ALIMENTA. Ponte en el papel COMPLETO de MI nicho:
investiga MIS apps líderes (búsqueda web/stores — no las asumas), MI público objetivo y MI
cliente ideal (FICHA-AVATAR con 57), y los NÚMEROS de MI mercado (FICHA-MERCADO). Nada se
hereda de otro nicho ni de los ejemplos ilustrativos del SO.

REFERENCIA VISUAL (opcional):
 • SI ADJUNTO una imagen de referencia: analízala siguiendo el ANÁLISIS DE REFERENCIAS de
   docs/sistema/INICIO.md y el protocolo REFERENCIA=CONTRATO de docs/sistema/16-DIRECCION-DE-ARTE.md.
   Extrae su dirección de arte completa (paleta y dónde usa el acento, tipografía, radios,
   tratamiento de gráficos y cards, densidad informativa) con la TABLA DE EXTRACCIÓN, mirando la
   imagen. La referencia MANDA sobre la capa anti-IA y las tablas del 29, y cada pantalla clave
   pasa el TEST DE FIDELIDAD. Quiero ESE nivel de pulido o mejor, FIEL a la referencia.
 • SI NO ADJUNTO imagen: no me la pidas ni la des por existente. La dirección visual se DERIVA
   completa con el PASO 0 del 16 (brief → arquetipo → mundo del sujeto → paleta/tipografía/motion)
   + la TABLA DE LÍDERES del 16 (las 3-5 apps líderes de MI nicho, investigadas) + la fila de MI
   nicho en 29-REFERENCIA-VISUAL.md (o la matriz audiencia×nicho si no hay fila) + el banco del
   54 para el dispositivo ownable. El modo (oscuro/claro) se deriva de MI audiencia — NO se asume
   por el nicho.

PROCESO (sigue el ciclo profesional de docs/sistema/12-FLUJO-AGENTICO.md):
1. Dirección de arte: con referencia adjunta → extracción REFERENCIA=CONTRATO + RÉPLICA FIEL
   del 54. Si NO adjunté referencia, ANTES de proponer diseño hazme LA PREGUNTA DE REFERENCIA
   del 54 (¿te propongo yo los estilos o tienes capturas de un estilo que te guste?); sin
   referencia → PASO 0 del 16. En todos los casos preséntame la FICHA-ARTE.md (paleta con hex,
   tipografía, craft, regla del acento, modo derivado y por qué) y ESPERA MI OK.
2. Define la idea, features (3-5 máx) y el App Brief siguiendo docs/sistema/01-IDEACION.md.
3. Diseña arquitectura y flujo con docs/sistema/04 y 15-PATRONES-UX.md.
4. DETENTE y muéstrame el plan visual + de pantallas antes de codear. ESPERA MI OK.
5. (tras mi OK) Construye aplicando RIGUROSAMENTE:
   - docs/sistema/14-LEYES-DE-DISENO.md (specs numéricas exactas)
   - docs/sistema/16-DIRECCION-DE-ARTE.md (identidad audaz y cohesiva, capa anti-IA)
   - docs/sistema/17-VISUALIZACION-DATOS.md (si la app muestra datos: anillos, barras, tendencias)
   - docs/sistema/15-PATRONES-UX.md (skeleton, empty states, micro-interacciones, háptica)
   - docs/sistema/11-DISENO-EMOCIONAL.md (personalidad, celebraciones, movimiento)
6. Verifica tsc + build + dev server en cada capa; cada pantalla se cierra con screenshot REAL
   a 375px puntuado por el SUBAGENTE revisor-visual (gate ≥36/40 y ≥16/20, + test de fidelidad
   si hubo referencia — regla 7 de CLAUDE.md). Test final: "si quito el logo, ¿se distingue de un
   template Y de las otras apps de este SO?" — y cierra actualizando ESTADO.md con el reporte de
   evidencia (ruta del screenshot + veredicto del revisor).

del 16 según mi audiencia concreta. Empieza por el punto 1.
